# League of Heroes 5.5E

Русскоязычный сайт сообщества «Лига Героев» с правилами, справочниками и инструментами для D&D 2024 (5.5E). Проект объединяет материалы Лиги, каталог игровых сущностей, пошаговый конструктор персонажа, экспорт в Roll20 и тестовый личный кабинет с авторизацией через Discord.

Изменения для игроков и мастеров собраны в [патчноутах](docs/PATCHNOTES.md). Документ обновляется вместе с контентом и пользовательскими возможностями сайта.
Источники и отметки «изменён эрратой» / «заменён новой версией» задаются по [гайду маркировки материалов](docs/material-marking.md).

## Возможности

- правила Лиги, эррата, активности простоя, бастионы и материалы о Сигиле;
- каталог разрешённых материалов с поиском, источниками, приоритетом редакции 2024 и ссылками на ограничения Лиги;
- исследование и путешествия: тематические правила и таблицы PHB/DMG 2024, поиск и переходы к глоссарию и эррате;
- боги и покровители: русские справки, публикации 5etools кроме EGtW, фильтры пантеонов и общий каталог с конструктором ([подробнее](docs/deities.md));
- 64 русских статблока компаньонов, призываемых существ и Мистической пушки в особенностях классов и 26 заклинаниях: сворачивание, три вкладки и внешние изображения ([подробнее](docs/companion-stat-blocks.md));
- справочники классов, видов, предысторий, черт, заклинаний, обычных и магических предметов;
- общий поиск из шапки и через Ctrl/Cmd+K, страница `/search` с фильтрами, ссылкой на запрос и поиском по текстам книг ([подробнее](docs/global-search.md));
- пошаговый конструктор персонажа с проверками выбора и локальным черновиком;
- экспорт черновика и готового листа персонажа в JSON для Roll20;
- калькуляторы Point Buy и сложности столкновений;
- браузерный редактор токенов с экспортом PNG;
- статистика игр на основе `stats.csv`;
- переключение светлой и тёмной темы, всплывающие подсказки и встроенный бросок кубов;
- тестовый личный кабинет игрока, мастера и администратора;
- Discord OAuth, облачное хранение персонажей и ключи синхронизации Roll20 через Supabase.

Личный кабинет, кампании и часть мастерских возможностей пока развиваются. Основные справочные страницы и локальные инструменты не требуют Supabase.

## Технологии

| Область | Решение |
| --- | --- |
| Сайт и маршрутизация | [Astro](https://astro.build/) 4 |
| Язык | TypeScript и клиентский JavaScript |
| База данных и авторизация | Supabase (`@supabase/supabase-js`) |
| Авторизация | Discord OAuth через Supabase Auth |
| Совместимость браузеров | `@vitejs/plugin-legacy` |
| Редактор токенов | Konva 8, загружаемый с CDN во время работы страницы |
| Хранение контента | TypeScript-модули и JSON в `src/data` |
| Основной менеджер пакетов | pnpm 11.9.0 |

Astro работает в стандартном статическом режиме: страницы и справочные API формируются во время сборки, а интерактивность выполняется в браузере. Серверный адаптер в проекте не подключён.

## Быстрый запуск

Понадобятся актуальная LTS-версия Node.js и pnpm версии, указанной в поле `packageManager` файла `package.json`.

```bash
pnpm install
pnpm dev
```

После запуска сайт доступен по адресу <http://localhost:4321>. Dev-сервер слушает все сетевые интерфейсы, поэтому его также можно открыть с другого устройства в локальной сети.

Если pnpm ещё не установлен, его можно активировать через Corepack (если Corepack входит в вашу установку Node.js):

```bash
corepack enable
corepack prepare pnpm@11.9.0 --activate
```

В репозитории присутствуют `pnpm-lock.yaml` и `package-lock.json`, но основной менеджер зафиксирован как pnpm. Чтобы не создавать лишние изменения lock-файлов, используйте pnpm для установки и обновления зависимостей.

| Команда | Назначение |
| --- | --- |
| `pnpm dev` | запустить dev-сервер Astro |
| `pnpm start` | псевдоним для `pnpm dev` |
| `pnpm check` | проверить Astro-компоненты и TypeScript |

Для отдельных подсистем есть тесты и браузерные сценарии в `src/utils` и `scripts`; проверки общего поиска описаны в [документации U01](docs/global-search.md). Перед публикацией рекомендуется выполнить как минимум:

```bash

pnpm build
```

### Как устроены данные

- классы лежат в `src/data/classes`, а публикуемый список собирается в `src/data/classes/index.ts`;
- виды лежат в `src/data/species`, предыстории — в `src/data/backgrounds`;
- черты, заклинания, предметы и магические предметы хранятся массивами в соответствующих `index.ts`;
- шаблон и справочные данные экспорта Roll20 находятся в `src/data/roll20`;
- изображения видов и классов размещаются в `public/images/species` и `public/images/classes`;
- страница `/tools/game-stats` читает корневой `stats.csv` во время сборки. CSV использует `;` как разделитель и формат `мастер;ОП;игрок;ОП;игрок;ОП;...`.

Чтобы добавить сущность с отдельной страницей, создайте или обновите модуль данных, подключите его в соответствующем `index.ts` и при необходимости добавьте изображение в `public/images`. Динамический маршрут включит запись в следующую статическую сборку.

## Конструктор персонажа и Roll20

Конструктор состоит из небольших шагов в `src/components/characterCreator/steps`, общей конфигурации и клиентских модулей экспорта. Его состояние сохраняется в `localStorage`, а при открытии облачного персонажа синхронизируется с таблицей `characters` в Supabase.

Пользователь может:

- выбрать вид, класс, предысторию, характеристики, владения, черты, снаряжение и заклинания;
- скачать переносимый JSON-черновик;
- подготовить JSON для листа **D&D 5E by Roll20**;
- сохранить героя в личном кабинете;
- подключить браузерное расширение Roll20 через отзывной ключ синхронизации.

Облачное сохранение использует поле `revision` для защиты от перезаписи более новой версии персонажа.

## Сборка и публикация

```bash
pnpm build
```

Результат создаётся в `dist/` и может размещаться на любом статическом хостинге. Переменные `PUBLIC_SUPABASE_*` должны быть доступны именно во время сборки, поскольку Vite встраивает их в клиентский код. В настройках Supabase также нужно разрешить production URL страницы `/test/auth/callback/`.

Для работы токенатора браузеру требуется доступ к `https://unpkg.com`, откуда загружается Konva. Остальные основные данные поставляются вместе со статической сборкой.

## Безопасность

- не коммитьте `.env` и `.env.*`; они уже исключены через `.gitignore`;
- не используйте `service_role` в клиентском коде или расширении;
- не отключайте RLS для пользовательских таблиц;
- применяйте миграции только к заранее проверенному проекту Supabase;
- перед публикацией проверяйте redirect URL Discord/Supabase для нужного домена.
