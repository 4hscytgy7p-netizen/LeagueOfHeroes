# План развития справочника Лиги Героев

Дата создания: 2026-10-05. Последнее обновление: 2026-10-09.

Цель: сделать сайт удобным справочником во время игры и обеспечить единые правила для персонажей, участвующих в партиях разных мастеров.

План составлен по анализу текущих страниц, компонентов и данных проекта. Уже существующие разделы указаны как основа для доработки. Их наличие не означает, что предложенная задача выполнена. Документ отслеживает работу; он не вводит новые правила Лиги.

## Как отмечать прогресс

1. Перед началом работы изменить статус задачи в таблице на «В работе».
2. По мере выполнения отмечать критерии готовности через `[x]`. Незавершённые критерии оставлять `[ ]`.
3. Если требуется решение по содержанию правил, использовать статус «Ожидает решения» и записать конкретный вопрос в журнале. Независимые части задачи можно продолжать.
4. Ставить «Готово», когда выполнены все критерии, проведены необходимые проверки и результат доступен в проекте. Локальная реализация и публикация сайта — отдельные события; факт публикации указывать явно.
5. В той же правке обновить сводку, дату последнего обновления и журнал: что изменено, как проверено, ссылки на файлы или PR, что осталось.
6. При изменении объёма задачи сохранить её ID и записать изменение в журнале. При добавлении задач пересчитать общее количество.

Статусы: **Запланировано**, **В работе**, **Ожидает решения**, **Готово**, **Отложено**. При откладывании указывать причину и условие возвращения к задаче.

Приоритеты: **P0** — согласованность действующих правил и исправление ошибок; **P1** — основные сценарии открытого стола; **P2** — расширение справочника и удобства; **P3** — развитие после основных задач. Приоритет отражает порядок старта, а не обязательную последовательность всех работ.

## Рекомендуемый порядок

1. **Допуск материала:** N01 — готово. Каталог опубликованных вариантов и совместимость редакций.
2. **Расширение по выбору пользователя:** N06, затем независимые N07–N09. Тематические справочники для игры.
3. **Улучшения справочника:** U01–U04, U07. Ускорить поиск, показать источники и связи, улучшить навигацию и подборки.
4. **Остальные улучшения:** U05–U06, U08–U09. Развить расчёты, доступность и печать.
5. **Дальнейшее развитие:** N10. Завершить игровую систему фракций после утверждения механик.

R01–R03 и N02–N05 исключены из текущей очереди до совместного решения мастеров. R03 приостановлена 2026-10-08: для дальнейшей работы нужны остальные мастера и данные третьего сезона. R04 возвращена в работу по прямому запросу пользователя; референс — DMG 2024, раздел planning-scenes.

N11 можно вести параллельно. Для новых тематических страниц использовать уже загруженные книги и данные, сохраняя ссылки на источники. Не поддерживать отдельные ручные копии одинаковых правил в нескольких разделах.

**R01–R03 отложены по решению пользователя.** Эти вопросы требуют совместного обсуждения с остальными мастерами открытого стола; локальный доступ к кабинету позволяет предварительно просмотреть материалы. Исключение от 2026-10-08: пользователь разрешил начать R04 независимо от остальных задач блока R.

Исключение от 2026-10-07: разрешён и выполнен анализ варианта R03 с конвертацией МОП в награды, без утверждения механики и изменения действующих правил. С 2026-10-08 R03 приостановлена до совместного обсуждения и получения данных третьего сезона.

**N02–N05 также отложены по решению пользователя.** Причина и условие возвращения такие же, как у блока R: совместное обсуждение с мастерами открытого стола и отдельное согласование начала работ. Следующая задача по выбору пользователя — N06.

### R03. Завершение правил денежной награды мастеру

**Отложено с 2026-10-08 по решению пользователя.** Самостоятельный этап исчерпан. Условие возвращения: участие остальных мастеров, данные третьего сезона открытого стола и отдельное согласование возобновления работ. Исследования сохранены; новые ставки и механика не приняты.

Основа: черновик `master-compensation` в [справочнике мастера](../src/data/masterRules.json).

2026-10-07: [критический разбор наброска с МОП](master-rewards-analysis.md) пересмотрен после уточнений пользователя и дополнен [эмпирическим анализом](master-rewards-evidence.md). МОП уже дают прогрессию, ОС и ДП, а накопительный лимит влитых МОП ≤ влитых обычных ОП действует в третьем сезоне. Цель R03 — компенсировать недополученную приключенческую добычу при одинаковом уровне, не дублируя ОС/ДП. Рекомендован имущественный бюджет одновременно с вливанием, с выбором полезных предметов и без обязательных осложнений; сравнивается альтернатива пакетов оснащения. Изучены 48 сообщений о 49 сессиях, проверен снимок источника статистики. Выборка не обосновывает окончательные ставки: уровни явно подписаны только для 66 из 205 участий, в диапазоне 1–8; есть неполные награды и расхождения CSV. Это исследовательский этап, а не принятие новой формулы.

Подтверждённые условия не выносятся на повторное согласование: начисление МОП за целые зачтённые часы, их применение для уровня, выдача ОС/ДП и накопительный лимит МОП/ОП сохраняются. Золото за повышение уровня — устранённое старое правило; его компонент уже не выводится в разделе прогрессии. Ожидаемые решения: достаточный ориентир оснащения сверх ОС/ДП, ставки и расчёт при пересечении уровней, бюджет или пакеты, каталог и оборот предметов, вывод золота, прежние вливания и крайние случаи учёта. Для калибровки нужны полные приключения известного сезона/этапа, с фактическим распределением добычи; текущие неполные итоги не заменяются нулями. До совместного решения новая имущественная механика и калькуляторы не вводятся.

### R04. Проверка CR и сохранение столкновений

Основа: [калькулятор столкновений](../src/pages/tools/encounter-builder.astro). Исходные ошибки: неизвестный CR принимался с 0 опыта, дробные количества обрезались, пустая группа давала неверную сложность и деление на ноль.

2026-10-08: реализованы [валидация и расчёт](../src/utils/encounterBuilder.ts), [браузерное сохранение](../src/scripts/encounterBuilder.ts) и мобильная форма. Расчёт сверен с DMG 2024, `planning-scenes`, стр. 97: бюджеты — верхние пределы, без множителя количества противников; превышение высокого бюджета показано отдельно. Для CR 0 доступны 0 и 10 опыта по статблоку. Пустые списки обрабатываются явно. Сохраняется одно столкновение с группой в текущем браузере; повреждённая запись защищена от автоматической перезаписи, запрет хранилища не мешает расчёту. Правила наград Лиги не изменены. Подробности, источники и команды проверок: [документация R04](encounter-builder.md).
