# Калькулятор столкновений: R04

Последнее обновление: **2026-10-08**. Адрес: `/tools/encounter-builder`.

Расчёт опирается на DMG 2024, [planning-scenes, стр. 97](../src/data/books/dmg-2024-ru/sections/planning-scenes.json), таблицу `p97-9` и раздел «Сложность сцены сражения». Все 20 строк бюджетов сверяются с локальной книгой тестом. Таблица опыта CR проверена по [официальным правилам 2024, How to Use a Monster](https://www.dndbeyond.com/sources/dnd/br-2024/how-to-use-a-monster).

Для группы разного уровня складываются индивидуальные бюджеты. Опыт противников суммируется без множителя за их количество. Поскольку книга предлагает расходовать бюджет, не превышая его, калькулятор относит столкновение к наименьшему бюджету, в который оно укладывается: низкому, среднему или высокому. Ровно бюджет относится к этой категории. Превышение высокого показывается как «Выше высокой», а не как дополнительная официальная категория. Это оценка для подготовки: окружение, необычные умения, ресурсы и тактика тоже влияют на реальный риск.

Пример: четыре персонажа 1 уровня имеют бюджеты 200 / 300 / 400. Противники на 200 опыта дают низкую оценку, на 250 — среднюю, на 400 — высокую, на 450 — выше высокой. Для пяти персонажей 3 уровня средний бюджет равен 1 125, для шести персонажей 15 уровня высокий — 46 800, как в примерах книги.

Принимаются CR 0, 1/8, 1/4, 1/2 и целые 1–30. Для CR 0 выбирается 0 или 10 опыта по статблоку. Количества должны быть положительными безопасными целыми, уровни — целыми 1–20; название противника — от 1 до 200 символов. Некорректные вводы и суммы за пределами точного целочисленного расчёта отклоняются целиком. Без группы сложность и опыт на персонажа не вычисляются; при пустом списке противников отображается просьба добавить их. Даже противники CR 0 без опыта считаются непустым столкновением.

Группа и противники автоматически сохраняются одним подготовленным столкновением в `localStorage`, ключ `league-encounter-v1`, формат с `version: 1`. После перезагрузки данные полностью валидируются и результаты пересчитываются. Хранилище относится к текущему браузеру и не синхронизируется с кабинетом или другим устройством. Повреждённое сохранение не перезаписывается до явной очистки. При недоступном хранилище расчёт продолжает работать, а интерфейс сообщает, что изменения могут не сохраниться. Очистка удаляет группу и противников после подтверждения и сохраняет пустое состояние.

Расчётный опыт не заменяет награды Лиги. R03 остаётся отложенной; правила ОП, МОП, ОС и ДП в этой задаче не меняются.

Проверки:

- `npm.cmd run test:encounters` — бюджеты книги, границы, примеры, CR, числовые поля, пустые списки, смешанные уровни и проверка сохранений.
- `node node_modules/typescript/bin/tsc --noEmit --target ES2022 --module ESNext --moduleResolution Bundler --allowImportingTsExtensions --skipLibCheck src/scripts/encounterBuilder.ts src/utils/encounterBuilder.ts` — типы изменённых модулей.
- `npm.cmd run build` — сборка сайта.
- `node scripts/check-encounters.mjs` — браузерная проверка при запущенном сервере на `http://127.0.0.1:4323`; адрес можно задать через `ENCOUNTER_PREVIEW_URL`. Использует имеющийся Playwright из `.book-import/browser` и установленный Chromium/Edge. Проверяет формы, Enter, безопасный вывод названий, сохранение и восстановление, удаление и очистку с отменой, повреждённое и запрещённое хранилище, ссылку на книгу, мобильный экран и темы; сохраняет скриншоты в `.book-import/encounters`.
