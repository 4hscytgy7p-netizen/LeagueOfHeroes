# Изображения классов: подготовка и кэширование

## Реализация

`src/components/classes/ClassCard.astro` импортирует PNG, на которые ссылаются данные классов, из `public/images/classes/`. Astro создаёт WebP во время сборки, сохраняя пропорции и прозрачность. Исходные PNG остаются без изменений.

Общая область арта имеет пропорции 4:5; `contain` показывает весь файл. Подпись находится отдельно. На телефоне до 600 px карточка превращается в строку. На больших экранах сетка содержит два, три или четыре столбца. На странице есть поиск по русскому/английскому названию и источнику, счётчик и сброс. Без JavaScript весь каталог остаётся доступным, а неработающее поле поиска скрыто.

Варианты ширины: 160, 320, 400 и 800 px. Размер ограничен шириной исходника: старые PNG 420×580 не увеличиваются искусственно. `srcset` и `sizes` позволяют браузеру выбрать подходящий вариант. Первые четыре изображения загружаются сразу, остальные используют `loading="lazy"`; декодирование асинхронное.

В создателе персонажа боковой портрет и иллюстрация в описании класса также используют `contain`, а перекрывающие рамку градиенты убраны.

## Рекомендуемые файлы

Для будущего арта сохраняйте исходник высокого качества с прозрачностью. Для формата нового апотекария рабочие размеры и бюджеты следующие:

| Назначение | Размер WebP | Предпочтительный вес | Получено для апотекария |
| --- | --- | --- | --- |
| Мобильная миниатюра | 160×173 | до 15 КБ | 8,4 КБ |
| Промежуточный вариант | 320×345 | до 40 КБ | 22,6 КБ |
| Обычная карточка | 400×431 | до 60 КБ | 30,4 КБ |
| Экран с высокой плотностью пикселей | 800×863 | до 120 КБ | 75,6 КБ |

КБ в таблице — 1000 байт. Высота округляется до целого пикселя; пропорции исходника сохраняются с точностью этого округления. При других пропорциях высота будет другой. Размер исходного `apothecary.png` — 1 685 665 байт; он не загружается в каталоге. Суммарный вес стандартных WebP шириной 400 px для всех 15 классов — 788 002 байта. Это не размер первого экрана: браузер может выбрать другой вариант, а загрузка остальных карточек отложена.

Не нужно вручную подготавливать все варианты: сборка уже делает это. Если будущий арт получается тяжелее бюджета, сначала оцените детали на реальном размере карточки и качество экспорта; бюджет является ориентиром, а не причиной портить иллюстрацию.

## Повторное посещение

Используется стандартный HTTP-кэш браузера. Файл `public/_headers` копируется Astro в `dist/_headers`; Netlify применяет его к статическим ответам. Для `/_astro/*`:

```http
Cache-Control: public, max-age=31536000, immutable
```

Оптимизированные файлы имеют хеш в URL. Пока файл находится в кэше и срок свежести не истёк, браузер может использовать его без запроса изображения к серверу. Изменение исходника или параметров экспорта создаёт новый URL при сборке — старый кэш не мешает обновлению. Отдельный выбранный размер изображения также имеет собственный URL и собственный кэш.

Для исходных `/images/classes/*`, которые используют стабильные имена, задано:

```http
Cache-Control: public, max-age=0, must-revalidate
```

Они могут храниться в кэше, но браузер проверяет актуальность на сервере. При неизменившемся файле и наличии валидатора сервер отвечает `304`, не передавая изображение заново. Эта настройка нужна оставшимся потребителям исходных PNG, в том числе создателю персонажа.

localStorage и cookies не используются для картинок. Они не дают преимуществ перед HTTP-кэшем; cookies ещё и передаются в HTTP-запросах. Service Worker и Cache API нужны, если появится отдельная задача офлайн-доступа с управлением версиями, но для быстрого повторного открытия каталога их добавлять не требуется.

Кэш не является гарантией постоянного хранения: очистка браузера, приватный режим, вытеснение, принудительная перезагрузка или выбор другого варианта могут вызвать новую загрузку.

После публикации проверить фактический ответ Netlify в DevTools → Network: у WebP должен быть указанный `Cache-Control`, а при обычном повторном открытии — загрузка из memory/disk cache. На локальной проверке кнопка Disable cache должна быть выключена. Локальный dev/preview-сервер Astro сам по себе не обязан применять `_headers`.

Официальные источники: [Netlify — custom headers](https://docs.netlify.com/manage/routing/headers/), [MDN — HTTP caching](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching), [Astro — assets API](https://docs.astro.build/en/reference/modules/astro-assets/).

## Проверка

Статическая сборка прошла: 2026 страниц, 60 оптимизированных вариантов изображений классов. В Chrome проверены обе темы, ширины 320, 390, 768, 1024 и 1440 px, число столбцов, отсутствие горизонтального переполнения и пересечения подписи с артом, поиск/пустой результат/сброс, клавиатурный фокус и отключение движения. Повторная загрузка изображений без новых запросов проверена на локальном сервере, применяющем правила подготовленных заголовков. Фактический production-ответ Netlify нужно проверять после публикации.

Общий `astro check` сообщает 1018 ошибок проекта. Диагностик для `classes.astro`, `ClassCard.astro` и `CharacterPreview.astro` нет; изменения в `CharacterWizard.astro` касаются только CSS. Общие ошибки не исправлялись в рамках этого изменения.
