# Как маркировать источник, адаптации, ограничения и новую версию материала

Метки задаются в файлах проекта и появляются после пересборки сайта. Формы для их редактирования в кабинете пока нет. Карточки, конструктор и каталог `/allowed-materials` используют общий каталог: отдельно менять каждую страницу не нужно.

## Где что задаётся

| Сведения | Файл / поле |
| --- | --- |
| Источник класса и подкласса | `src/data/classes/*.ts` → `sourceBook` |
| Источник вида и его варианта | `src/data/species/*.ts` → собственное `sourceBook` |
| Источник предыстории | `src/data/backgrounds/*.ts` → `sourceBook` |
| Источник черты | `src/data/feats/index.ts` → `sourceBook` |
| Источник заклинания | `src/data/spells/index.ts` → `source.book`, `source.page` |
| Источник обычного предмета | `src/data/items/index.ts` → `sourceBook` |
| Источник магического предмета | `src/data/magicItems/index.ts` → `source.book`, `source.page` |
| Связи с правилами Лиги и явная замена | [`src/data/materialAnnotations.ts`](../src/data/materialAnnotations.ts) |
| Стабильные ID правил и адреса разделов | [`src/data/leagueRules.ts`](../src/data/leagueRules.ts) |
| Тексты действующих правил | Тематические компоненты `src/components/rules/equipment`, `species`, `combat`, `general/mechanics` |
| Сборка общего каталога | `src/data/materials.ts`, правила сравнения — `src/utils/materialCatalog.ts` |

У подкласса можно добавить отдельное `sourceBook`. Для существующих данных сохранено чтение кода из конца `nameEn`, например `Tempest Domain PHB14`; явное поле имеет приоритет. Подкласс и вариант вида не наследуют источник родителя.

## Источник и редакция

```ts
sourceBook: 'PHB24', // Книга игрока, правила 2024
sourceBook: 'XGE14', // XGE, правила 2014
// Для заклинаний и магических предметов:
source: { book: 'PHB24', page: 245 },
```

Коды `PHB24`, `PHB'24` и ``PHB`24`` равнозначны. Суффикс `14` или `24` означает редакцию правил, а не год выпуска книги. Если источник или редакция неизвестны, не угадывайте их: интерфейс покажет «Источник не указан» или «Редакция не указана». Это само по себе не запрещает опубликованный материал.

## «Адаптировано для Лиги» и «Ограничения Лиги»

Описания сайта уже могут включать адаптации для открытого стола. Отсутствие метки не подтверждает совпадение с оригиналом. Не пытайтесь восстановить все отличия от книг по старой эррате: она не была их полным перечнем.

Откройте `src/data/materialAnnotations.ts` и добавьте запись в `materialAnnotations`. Существующий пример для пистоля:

```ts
{
  kind: 'item',
  id: 'pistol',
  errata: [{
    type: 'restriction',
    href: '/rules/equipment#weapon-restrictions',
    note: 'Из огнестрела разрешены только Пистоль и Мушкет.',
  }],
},
```

`href` ведёт к разделу с действующим правилом; `note` — краткое пояснение, видимое рядом с меткой в карточке. Несколько правил можно указать несколькими элементами `errata`. Имя поля `errata` сохранено для совместимости; оно теперь хранит оба типа связей. Если запись для материала уже есть, дополните её: две записи с одинаковыми `kind` и `id` считаются ошибкой.

- `type: 'restriction'` — отдельное общее правило действует вместе с описанием. Метка: «Ограничения Лиги». При отсутствии `type` используется этот же вариант для совместимости.
- `type: 'adaptation'` — подтверждённое изменение уже включено в описание. Метка: «Адаптировано для Лиги», пояснение начинается с «Уже учтено в описании». Для неё обязательно непустое `note` с конкретным отличием. Сначала исправьте текст и нужные расчёты, затем добавьте метку. Ссылка может вести на пояснение в самой карточке.

Метки не изменяют механику, расчёты или проверки конструктора автоматически. Не отмечайте адаптацию на основании одного лишь отличия формулировки или наличия книги в источниках. Сначала опубликуйте текст правила и убедитесь, что якорь существует, затем добавьте связь. Тематические правила используют `RelatedMaterials.astro` для обратных ссылок по тому же адресу; отдельную копию списка затронутых материалов вести не нужно.

Сейчас проверены связи опубликованных ограничений оружия, контейнеров, увеличенного оружия и названных в правиле компонентов зачарованных предметов. Метки встроенных адаптаций не расставлялись без сравнения конкретного описания с источником. Общие правила параметров видов доступны из заголовков карточек; травмы доступны из общих правил и исследования и не привязаны произвольно ко всем заклинаниям или предметам.

## «Заменён новой версией»

Для одинакового английского названия и типа материала каталог автоматически связывает версию 2014 с единственной опубликованной версией 2024. Для подклассов и вариантов видов также должен совпадать родитель. Если новых кандидатов несколько, автоматической замены нет: укажите её явно.

Явная связь нужна при переименовании, несовпадении названий или неоднозначном сравнении. Она задаётся **у старой записи**:

```ts
// Пример формата: сначала должны существовать обе записи черты.
{
  kind: 'feat',
  id: 'old-feat-id',
  replacedBy: { kind: 'feat', id: 'new-feat-id' },
},
```

Оставьте старую запись и её ID, чтобы прежние ссылки и выборы персонажей продолжали работать. Новому тексту создайте отдельную запись с новым ID и собственным источником. Метка старой версии ведёт на новую карточку; при цепочке замен ссылка ведёт к последней версии. Каталог не переносит выбор сохранённого персонажа автоматически.

Чтобы отключить ошибочное автоматическое совпадение для конкретной записи:

```ts
{ kind: 'feat', id: 'existing-feat-id', replacedBy: null },
```

Правила Лиги и замена могут быть в одной записи: используйте вместе `errata` и `replacedBy`. В карточке появятся соответствующие метки, а каталог найдёт материал как по фильтру «Адаптации и ограничения Лиги», так и по фильтру замены.

## Как найти `kind` и `id`

| Материал | `kind` | `id` |
| --- | --- | --- |
| Класс | `class` | ID записи класса, например `cleric` |
| Подкласс | `subclass` | `ID-класса:ID-подкласса` |
| Вид | `species` | ID записи вида, например `elf` |
| Вариант вида | `species-variant` | `ID-вида:ID-варианта`; если собственного ID нет — `ID-вида:индекс` (с нуля) |
| Предыстория | `background` | ID записи предыстории |
| Черта | `feat` | ID записи черты |
| Заклинание | `spell` | ID записи заклинания |
| Обычный предмет | `item` | ID записи предмета, например `pistol` |
| Магический предмет | `magic-item` | ID записи магического предмета |

Исходный ID находится в записи материала в `src/data`. В HTML карточки общий ключ виден в `data-material-key`, например `item:pistol`. Для вариантов видов, на которые добавляете ручные связи, лучше сначала задать постоянный `id` в исходной записи: индекс меняется при перестановке массива. После добавления ID обновите уже существующие связи на этот вариант.

## Проверка и снятие меток

1. Выполните `npm run test:materials` и `npm run build`. Сборка отклоняет неизвестные ID, дубликаты связей, циклы замен и замену материалом другого типа или другого родителя. Ссылки должны быть внутренними, вида `/страница#якорь`.
2. Откройте карточку и `/allowed-materials`, проверьте метку и переход по ней. Для подкласса или варианта вида переключите селектор. Если материал доступен конструктору, проверьте его там.
3. Проверьте именно содержание целевого правила: успешная сборка не подтверждает правильность текста, наличие страницы или якоря. Для готовой сборки можно запустить `node scripts/check-material-metadata.mjs` с локальным preview; он проверяет метки, ссылки и якоря.
4. Обновите `docs/PATCHNOTES.md` описанием заметного игрокам изменения.

Для снятия отметки правила Лиги удалите соответствующий элемент `errata`; если других связей нет, удалите всю запись. Удаление `replacedBy` возвращает автоматическое сравнение 2014/2024. Чтобы убрать и автоматическую метку замены, поставьте `replacedBy: null`.

Не редактируйте `dist`: это результат сборки, который будет перезаписан. Публикация сайта выполняется отдельно от локальной пересборки.
